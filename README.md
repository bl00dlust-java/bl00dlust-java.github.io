# Кибергигиена — бесплатная платформа цифровой безопасности

Русскоязычный учебный проект, который объединяет обучение, безопасную практику, базу знаний и полезные инструменты. Публичная версия размещается на GitHub Pages.

## Что уже есть

- 6 учебных модулей с уроками и тестами.
- Неограниченные повторные попытки и разбор ответов.
- Сохранение темы и учебного прогресса в браузере.
- Светлая и тёмная темы с учётом системной настройки.
- Сертификат для печати или сохранения в PDF после прохождения курса.
- Практическая лаборатория с вымышленными учебными сценариями.
- База знаний, словарь, официальные источники и чек-листы.
- Бесплатные инструменты, которые по возможности обрабатывают данные прямо в браузере.
- Панель редактирования материалов и учебных сценариев.

Сайт не требует регистрации. В текущей версии прогресс хранится на устройстве посетителя. Облачные профили и синхронизация между устройствами пока не реализованы.

## Технологии

- React 18 и TypeScript — для нового интерфейса и компонентов.
- Vite — для локального запуска и сборки.
- Tailwind CSS и обычный CSS — для оформления.
- Статические HTML/CSS/JavaScript-страницы — для существующих разделов курса, лаборатории и редакторов.
- JSON-файлы в `data/` — для материалов и учебных сценариев.
- GitHub Pages — для бесплатной публикации публичной версии.

В репозитории пока сосуществуют новое React-приложение и ранее созданные статические страницы. Не удаляйте старые файлы, пока не проверены все ссылки и сценарии.

## Требования

- Node.js LTS.
- npm.

## Локальный запуск

В корне репозитория выполните:

```powershell
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://localhost:5173`.

## Проверка и сборка

```powershell
npm run typecheck
npm run typecheck:legacy
npm run build
npm run preview
```

- `typecheck` проверяет TypeScript нового приложения.
- `typecheck:legacy` проверяет старую TypeScript-часть, если её конфигурация и зависимости установлены.
- `build` проверяет типы, собирает Vite-приложение и копирует необходимые статические разделы в `dist/`.
- `preview` запускает локальный просмотр готовой сборки.

После сборки проверьте, что в `dist/` присутствуют все страницы и ресурсы, на которые ведут ссылки.

## Основные папки и файлы

- `index.html` — точка входа публичной страницы.
- `src/` — React-приложение, компоненты и стили.
- `admin/dashboard.html` — точка входа React-панели управления.
- `admin/` — существующие редакторы и вспомогательные страницы панели.
- `classic.html`, `hub.html` — классический курс и дополнительные разделы.
- `src/app.ts`, `js/app.js` — логика старого курса и собранный браузерный файл.
- `css/`, `js/` — стили и сценарии статических разделов.
- `data/hub-content.json` — материалы базы знаний, словарь и внешние источники.
- `data/simulators.json` — вымышленные учебные сценарии.
- `scripts/` — скрипты сборки и проверки контента.
- `docs/PROJECT-IMPLEMENTATION-PLAN.md` — план реализации, бесплатная архитектура и критерии готовности.

## Безопасность

- Не вводите в учебные тренажёры настоящие пароли, коды подтверждения, платёжные данные или другую конфиденциальную информацию.
- Тренажёры должны использовать только вымышленные примеры и не выполнять действия на реальных сайтах.
- Генератор паролей использует Web Crypto API браузера.
- Не добавляйте секреты, API-ключи или административные токены в исходный код, JSON-файлы, коммиты или публичные настройки.
- Существующая панель управления использует GitHub Contents API: владелец вводит токен вручную. Это не полноценная серверная авторизация и не система ролей. Не считайте скрытую ссылку на страницу администрирования защитой доступа.
- Не используйте панель с токеном на общедоступном устройстве и отзывайте токен, если он мог стать доступен посторонним.

## Бесплатная инфраструктура

Основная публичная часть остаётся статической и публикуется через GitHub Pages. Для облачных профилей, синхронизации и защищённого управления пользовательскими данными потребуется отдельный backend и база данных. Их выбор ещё не завершён: сравниваются только бесплатные варианты. Не подключайте платные тарифы и не включайте оплату сверх бесплатных лимитов.

Бесплатные сервисы могут иметь ограничения по объёму, активности и количеству запросов. При достижении лимита сайт должен показать понятное сообщение и сохранить возможность пользоваться локальными материалами, а не обещать неограниченную работу.

## Публикация

Публикация выполняется через GitHub Pages. Перед запуском:
1. Выполните `npm run build`.
2. Проверьте все основные маршруты и ресурсы внутри `dist/`.
3. Проверьте мобильную версию, светлую/тёмную темы и сценарии курса.
4. Убедитесь, что в публичной сборке нет секретов и тестовых персональных данных.
5. Опубликуйте проверенную сборку из настроенной ветки/папки GitHub Pages.

Подробные этапы разработки и критерии готовности находятся в `docs/PROJECT-IMPLEMENTATION-PLAN.md`.
