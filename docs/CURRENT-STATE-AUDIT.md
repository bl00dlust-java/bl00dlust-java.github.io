# Технический аудит и журнал первых исправлений

Дата: 4 ноября 2026 года  
Ветка: `main`  
Репозиторий: `bl00dlust-java/bl00dlust-java.github.io`

## Подтверждённое состояние

### Технологии и сборка
- В `package.json` объявлены React 18, TypeScript 5, Vite 6 и Tailwind CSS 3.
- Команды проекта: `dev`, `build`, `preview`, `typecheck`, `typecheck:legacy`, `validate:content`, `validate:build`.
- Строгая проверка TypeScript теперь включает и публичный React-прототип, и React-панель управления (`src/main.tsx`, `src/react-app.tsx`, `src/admin-main.tsx`, `src/admin-app.tsx`).
- Команда сборки после копирования статических страниц проверяет структуру материалов и наличие обязательных HTML-страниц/локальных ссылок в `dist/`.
- Vite собирает `index.html` и `admin/dashboard.html`.
- `admin/dashboard.html` явно подключает `src/admin-main.tsx`.
- В `index.html` на момент аудита подключены старые браузерные скрипты из `js/`; React-точка входа `src/main.tsx` в этой странице не подключена.
- Поэтому React-компонент главной страницы в `src/react-app.tsx` нельзя считать действующей публичной главной страницей без дополнительной проверки. Старый и новый интерфейсы существуют параллельно.

### Действующие разделы
- Старый курс запускается через `index.html` и `js/app.js`.
- Дополнительные разделы открываются через `hub.html` и `js/hub.js`.
- Материалы и учебные сценарии находятся в `data/hub-content.json` и `data/simulators.json`.
- Есть локальные редакторы контента и сценариев в `admin/`.
- Прогресс и настройки сохраняются в браузере; общей облачной базы пользователей пока нет.

### Администрирование и безопасность
- Существующая панель использует GitHub Contents API.
- Токен вводится владельцем вручную; в просмотренном начале `admin/admin.js` он хранится в переменной текущей страницы, а не задан константой в исходниках.
- Это не серверная система ролей и не полноценная авторизация. Публичную страницу администрирования нельзя считать защищённой только потому, что на неё не ведёт меню.
- В кодовом поиске проверены типовые признаки случайного хранения токенов в localStorage и константных секретов: совпадений не обнаружено. Это полезная первичная проверка, но не полноценный аудит всех потоков данных и сетевых запросов.

## Основные риски перед расширением

1. **Две реализации интерфейса.** Если продолжать развивать обе параллельно, изменения будут дублироваться и расходиться.
2. **Неоднозначная точка входа.** Нужно решить, остаётся ли старый статический интерфейс основной версией или React-страница заменит его после проверки.
3. **GitHub Pages не является backend.** Он подходит для публикации публичных страниц, но не для защищённого хранения общих профилей и синхронизации.
4. **Клиентский токен администратора.** Ручной токен не должен становиться частью публичной системы администрирования. Для долгосрочного решения нужен серверный слой или другой безопасный процесс публикации.
5. **Нет общей статистики пользователей.** Локальный прогресс в браузере нельзя выдавать за глобальную аналитику посещений.
6. **Бесплатная инфраструктура ограничена.** До включения облачных функций нужно определить поведение при остановке сервиса, превышении квот и потере соединения.

## Рекомендуемый порядок первых технических действий

1. Создать резервную точку текущего состояния и проверить последний успешный workflow GitHub Actions.
2. Локально установить зависимости и выполнить `npm run typecheck`, `npm run build`.
3. Исправить найденные ошибки сборки, не меняя поведение публичных страниц.
4. Составить список всех страниц и ссылок, проверить мобильную версию и светлую/тёмную темы.
5. Выбрать одну основную реализацию главной страницы и навигации; старые страницы удалять только после проверки замен.
6. После стабилизации публичной версии отдельно прототипировать анонимный профиль на бесплатном backend.

## Уже внесённые изменения

- Добавлен `scripts/validate-build.mjs`: проверяет обязательные файлы публикации, локальные ссылки HTML, выход ссылок за пределы `dist/` и синтаксис основных JSON-материалов.
- Команда `build` теперь запускает проверку TypeScript, Vite, копирование старых страниц, проверку контента и проверку итоговой сборки.
- `typecheck:legacy` изменён на `tsc --noEmit -p tsconfig.json`, чтобы проверка старого TypeScript не перезаписывала `js/app.js`.
- Workflow качества теперь проверяет старый TypeScript, получает исходники перед запуском CodeQL и не сканирует `node_modules/` и `dist/` командой `node --check`.
- Добавлен `.gitignore` для зависимостей, результатов сборки, локальных переменных окружения и логов.
- Синтаксис нового скрипта проверки сборки отдельно проверен Node.js 22. Полная сборка проекта в этой среде пока не запускалась.

## Ограничение текущей проверки

Исходники и настройки прочитаны через подключённый GitHub-доступ. Клонировать репозиторий в локальную среду и запустить npm-команды в этой сессии не удалось из-за отсутствия сетевого доступа к GitHub. Поэтому успешная сборка и прохождение тестов пока **не подтверждены**.
