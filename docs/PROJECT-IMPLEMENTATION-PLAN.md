# План реализации платформы «Кибергигиена»

> Рабочий документ. Цель — бесплатная рабочая демонстрационная версия, которую реально поддерживать одному разработчику. Платные функции, обязательные подписки и платные API не используются.

## 1. Цель и ограничения

Создать русскоязычную платформу, объединяющую:
- понятное обучение цифровой безопасности;
- безопасную практику и учебные симуляторы;
- повседневные инструменты и инструкции;
- базу знаний, новости и официальные источники;
- локальный прогресс и мотивационные элементы без публичных рейтингов;
- простую панель управления материалами.

Аудитория — все пользователи интернета, в том числе люди без технической подготовки. Тексты должны объяснять термины простым языком.

**Главное ограничение:** проект демонстрационный и должен быть завершён в короткий срок. Сначала реализуются устойчивые основные сценарии, а не сложная инфраструктура ради будущего масштаба.

## 2. Зафиксированные продуктовые решения

### Общая концепция
- Объединить обучение, практику и инструменты повседневной помощи.
- Сохранить существующую основу и визуальное направление сайта, постепенно улучшая их.
- Поддерживать ПК, планшеты и смартфоны.
- Основные направления должны быть самостоятельными, но иметь общую навигацию и связанный прогресс.

### Обучение
- Курсы и модули, короткие уроки примерно по 5–10 минут.
- Интерактивные задания, тесты и повторные попытки.
- Игровые элементы и достижения.
- Практические темы: пароли, фишинг, приватность, устройства, утечки и восстановление доступа.
- При возвращении — предложение продолжить обучение или перейти на главную.

### Лаборатория и практика
- Разные виды безопасной практики.
- Продвинутые учебные сценарии, но без действий на реальных сайтах и без отправки настоящих сообщений.
- Пользователь сам выбирает сценарий.
- После упражнения показываются краткий результат и рекомендации.
- Связь с обучением, профилем, достижениями и статистикой.
- Лаборатория — отдельный раздел.

### Инструменты
- Категории: пароли, ссылки, приватность, чек-листы, действия при инцидентах, файлы и другие полезные инструменты.
- Инструменты бесплатные.
- Обработка по возможности выполняется локально в браузере; настоящие пароли и секреты не отправляются на сервер.
- Каталог инструментов — комбинированный.

### База знаний и материалы
- Разделы: guides, dictionary, incidents, news, official, downloads, research, cases.
- Комбинированная расширенная организация материалов.
- Новости смешанного формата, обновления по значимым событиям.
- Материалы доступны всем посетителям.

### Игровая система
- XP, уровни, достижения, серии активности, статистика, задания и квесты.
- Награды преимущественно косметические.
- Общий прогресс по платформе.
- Соревнования — только по желанию.
- Мотивация должна оставаться сбалансированной и не давить на пользователя.

### Локальный анонимный профиль
- Регистрация, пароль и обязательный email отсутствуют.
- При первом посещении создаётся случайное имя и анонимный ID; имя можно изменить.
- На устройстве локально хранятся прогресс, достижения, настройки, история и закладки.
- Профиль не является учётной записью и не синхронизируется между устройствами.
- Перенос данных между устройствами не обещается в демонстрационной версии.
- Пользователь должен иметь понятный способ сбросить локальные данные; экспорт/импорт можно рассматривать отдельно, если это будет безопасно и укладываться в срок.

### Администрирование
- Визуальное редактирование контента, черновики, предварительный просмотр и публикация.
- Поиск и фильтрация материалов, версии и журнал изменений.
- Не создавать фиктивных пользователей, сообщества или статистику. Поскольку регистрации и пользовательского сообщества нет, соответствующие пункты не должны изображать реально работающие функции.

## 3. Технические решения и сравнение

### Варианты хранения и серверной части

| Вариант | Плюсы | Минусы | Вывод |
|---|---|---|---|
| Только GitHub Pages + localStorage | Бесплатно, просто, уже используется | Нет защищённой общей базы и синхронизации между устройствами | Оставить для публичной части и локального гостевого режима |
| Supabase Free | PostgreSQL, API, авторизация, правила доступа; бесплатный тариф | Проект может приостанавливаться после 7 дней низкой активности; нет автоматических бэкапов на Free | Кандидат для первого прототипа профилей |
| Firebase Spark + Firestore | Анонимная авторизация, документная база, бесплатные дневные квоты | При превышении квоты соответствующая функция блокируется до следующего периода; бэкапы требуют платных функций | Альтернатива, если удобнее экосистема Google |
| Cloudflare Workers + D1 | Бесплатные лимиты для небольшого проекта, полный контроль API и схемы БД | Больше собственного серверного кода; сложнее безопасно реализовать восстановление и права доступа | Не выбирать для первого короткого этапа |

**Утверждённое направление для демонстрационной версии:** GitHub Pages для публичного статического сайта и localStorage для локального прогресса и настроек. Backend, облачные профили и синхронизация между устройствами не входят в текущий объём. Не подключать платные сервисы и не обещать серверные функции, которых нет.

### Безопасность
- Минимально необходимые права доступа.
- Проверка прав на сервере, а не только скрытие кнопок в интерфейсе.
- Не хранить секреты в репозитории, HTML, JavaScript или localStorage.
- Резервное копирование и проверка восстановления в пределах бесплатных возможностей.
- Журнал важных административных действий без записи паролей, токенов и кодов восстановления.
- Защита от спама и злоупотреблений.
- Проверка пользовательского ввода и ограничение частоты запросов.
- Мониторинг доступности и понятная обработка ошибок.
- Автоматические проверки сборки и тесты ключевых сценариев.

### Архитектура приложения
- Модульная структура: отдельные части для академии, лаборатории, инструментов, базы знаний, инцидентов, локального прогресса, настроек и администрирования.
- Не создавать отдельные микросервисы: для проекта достаточно одного клиентского приложения и, если подтвердится необходимость, одного backend/API.
- Публичные материалы по возможности хранить в файлах JSON/Markdown в репозитории.
- Секретные и пользовательские данные не хранить в публичном репозитории.

## 4. План разработки

### Этап 0. Проверка существующего проекта
- Зафиксировать текущую структуру и точку возврата.
- Проверить сборку, ссылки, адаптивность, консоль браузера и текущие тесты.
- Найти дублирующие реализации старого и нового интерфейса.
- Уточнить, какая версия является основной, чтобы не поддерживать две параллельные версии без необходимости.

### Этап 1. Надёжная основа
- Сохранить существующий дизайн и привести общую навигацию к единому виду.
- Убедиться, что главная страница, обучение, лаборатория, база знаний и инструменты корректно работают на мобильных устройствах.
- Сохранить гостевой режим и локальное хранение прогресса.
- Проверить доступность, клавиатурную навигацию и поддержку уменьшения анимации.

### Этап 2. Контент и обучение
- Привести модули, уроки и тесты к единому формату данных.
- Добавить недостающие инструкции, словарь, чек-листы и официальные источники.
- Проверить правильность ответов, объяснений и ссылок.
- Довести безопасные симуляторы до законченных учебных сценариев.

### Этап 3. Инструменты
- Реализовать бесплатные инструменты с локальной обработкой.
- Проверить, что секреты и введённые пользователем данные не уходят на сторонние серверы.
- Добавить понятные предупреждения и инструкции.

### Этап 4. Локальный профиль и прогресс
- Создать анонимный профиль без регистрации и пароля.
- Сохранять прогресс, достижения, настройки, историю и закладки локально.
- Реализовать понятный сброс данных и обработку ситуации, когда localStorage недоступен.
- Не добавлять облачную синхронизацию в демонстрационную версию.

### Этап 5. Админ-панель
- Сначала безопасное редактирование учебных материалов, словаря, ссылок и сценариев.
- Публикация через черновик и подтверждение.
- Ограничить доступ к операциям публикации.
- Не размещать секретный административный токен в клиентском коде или публичных файлах.
- Расширенные роли и аналитика — только если останется время и есть бесплатный безопасный способ.

### Этап 6. Проверка и публикация
- Полная проверка основных функций, адаптивности, безопасности и производительности.
- Проверка на ПК, планшете и смартфоне.
- Проверка локального профиля, сохранения прогресса, сброса данных и поведения при недоступности localStorage.
- Проверка ссылок, ошибок и сценариев отказа backend.
- Полный запуск демонстрационной версии на GitHub Pages.
- Подготовить документацию и инструкцию администратора.

## 5. Критерии готовности демонстрационной версии

1. Сайт открывается по публичной ссылке и корректно выглядит на основных размерах экрана.
2. Пользователь может пройти курс, тесты и повторить попытку.
3. Практические сценарии безопасны и дают объяснение результата.
4. База знаний, словарь, новости и официальные ссылки доступны.
5. Инструменты работают без платных API и не передают секреты без необходимости.
6. Гостевой прогресс работает предсказуемо.
7. Если включён backend — профиль можно восстановить и удалить; права доступа проверяются на сервере.
8. Админ-панель не раскрывает токены и не выдаёт фиктивную статистику за реальные данные.
9. Сборка и основные проверки проходят без ошибок.
10. Документация позволяет запустить, опубликовать и продолжить разработку проекта.

## 6. Документация, которую нужно подготовить

- Архитектура сайта.
- Установка и локальный запуск.
- Руководство администратора.
- Руководство пользователя.
- Описание API и взаимодействия частей сайта.
- Документация по безопасности.
- Инструкция для дальнейшей разработки.
- Инструкция по публикации.

## 7. Что пока не следует считать утверждённым

- Окончательный выбор backend и базы данных.
- Конкретный формат API и схема облачной БД.
- Частота синхронизации и правила разрешения конфликтов.
- Политика резервного копирования на выбранном бесплатном сервисе.
- Полный набор ролей сообщества и админ-панели.
- Состав систем 2–4: их прежние ответы не удалось достоверно восстановить. До отдельного подтверждения они не должны расширять объём первой демонстрационной версии.

## 8. Текущая отправная точка

Репозиторий: `bl00dlust-java/bl00dlust-java.github.io`, ветка `main`.

В проекте уже присутствуют:
- React 18, TypeScript, Vite и Tailwind CSS;
- отдельная React-страница админ-панели;
- классическая версия курса и дополнительные статические страницы;
- локальное сохранение темы и прогресса;
- лаборатория, база знаний, инструменты и JSON-файлы материалов;
- редакторы контента и сценариев, использующие GitHub Contents API.

Обнаружено архитектурное расхождение: README описывает сайт как простой статический TypeScript-проект, а package.json и Vite уже содержат React-приложение. Старые статические страницы и новое React-приложение существуют параллельно. Первое техническое действие — проверить сборку и определить единую основную точку входа, не удаляя работающие страницы до проверки.
